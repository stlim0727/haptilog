# Discussion #66: 웹 체류·내 장소·추천 작업 분할

상태: 구현 전 작업 명세. 2026-10-26. [Discussion #66](https://github.com/stlim0727/haptilog/discussions/66)의 체류 중심 계획을 구현 단위로 나눈다. 제품 코드를 변경하거나 원격 데이터를 쓰는 작업은 이 문서 작성 범위에 포함하지 않는다.

## 확인한 현재 구조

- `web/src/main.tsx`가 녹음 조회·인증·필터·데스크톱 화면을 조립하고 `MobileWorkspace.tsx`가 모바일 화면을 구성한다. 양쪽의 대규모 동시 수정은 피한다.
- `RecordingMap.tsx`는 녹음 GPS만 표시하며 위치가 있는 녹음이 없으면 지도를 초기화하지 않는다. 장소 편집 지도로 그대로 사용하면 음성 없는 체류와 수동 장소 등록이 막힌다.
- `domain.ts`의 `Recording`은 원본 위치·시간을 가진다. 체류 연결 때문에 이를 변경하지 않는다. 현재 날짜 필터는 브라우저 시간대를 사용한다.
- 현재 웹의 녹음 기반 장소 묶음은 사용자가 저장한 GPS 원형 장소와 다르다. 새 도메인은 `SavedPlace`처럼 구분해 기존 집계를 재해석하지 않는다.
- 현재 연결 브라우저 접근은 워치 소유권과 세션별 권한에 의존한다. 브라우저 자신의 UID를 워치 owner로 가정하지 않는다. 서버 권한 계약은 동기화 담당이 정의한다.

## 범위와 공통 계약 선행조건

터치 기록·상시 수집·이동 궤적 재구성·AI 분류는 제외한다. 체류를 배경으로 음성을 탐색하며 기존 음성 목록을 유지한다. 장소 등록 없이 감지한 체류가 출발점이다. 기본 체류 기준 10분, 5·10·20·30분 공통 설정이며 장소별 시간 설정은 만들지 않는다.

다음은 웹에 필요한 **논리 계약**이다. 실제 필드명과 테이블/RPC는 동기화 계약 확정 후 매핑하며 웹이 독자적으로 백엔드 스키마를 정하지 않는다.

| 객체 | 웹에 필요한 정보 |
| --- | --- |
| Stay | 안정적인 ID와 revision, owner 범위, session/continuity 식별, startedAt, lastObservedAt, 선택적 exitConfirmedAt, 활성/종료 상태와 종료 이유, 대표 좌표·정확도, 선택적 장소 연결 및 관측 당시 이름 |
| SavedPlace | ID·revision, 이름·중심·반경, 삭제 상태, 워치 적용 revision/적용 대기 상태 |
| Settings | 별도 위치 동의 상태, 공통 체류 시간, 보존 기간, 소급 업로드 선택 상태 |
| Sync status | 마지막 동기화·관측 시각, 미수신/오래됨/권한 만료/오프라인 상태; 동기화 시각만으로 현재 체류를 주장하지 않음 |
| Association | 체류↔녹음의 재생성 가능한 연결, 자동/명시적 사용자 선택 구분; 원본 녹음 행·파일을 변경하지 않음 |
| Dismissal | owner별 추천 숨김 식별자와 재계산 후에도 같은 후보를 억제할 위치 매칭 규칙 |

UTC 시각을 저장·전송하고 표시 시간대는 기존처럼 브라우저 시간대로 명시한다. 자정·일광절약시간 전환을 캘린더 경계로 계산하며 하루를 고정 24시간으로 나누지 않는다. 조회는 해당 날짜와 **겹치는 체류**를 포함해야 하므로 시작 시각만 필터링하지 않는다. 보존 만료·삭제·권한 변경 후의 캐시는 재사용하지 않는다.

## 병렬 작업 목록

각 작업의 테스트·스타일·문구도 해당 작업자가 소유한다. 새 기능의 문구는 `location-stays/copy.ts`, 스타일은 `location-stays/stays.css`에 모아 `i18n.ts`, `style.css`, `mobile.css`의 동시 편집을 줄인다. 폴더·파일명은 제안이며 계약 단계에서 고정한다.

### WEB-01 — 도메인 계약·테스트 fixture·read model

- **소유:** `web/src/location-stays/types.ts`, `domain.ts`, `domain.test.mjs`, `fixtures.ts`.
- **선행:** 워치/동기화 담당과 논리 계약 합의. fixture 설계와 함수 골격은 즉시 시작 가능.
- **작업:** 시각·좌표·반경 검증, 날짜별 체류 표시 조각 생성, 활성 상태의 freshness 판정, 녹음 연결 후보 계산을 순수 함수로 분리한다. 장소가 겹치거나 연결 후보가 여러 개인 경우 임의 선택하지 않는 결과 타입을 제공한다.
- **완료:** 같은 체류의 자정 분할은 원 ID 유지. 표시 시간은 lastObservedAt까지이며 exitConfirmedAt까지의 미관측 시간을 가산하지 않는다. 3분 초과 공백·세션 경계는 연결하지 않는다. 삭제·만료·쓰레기통 녹음은 자동 연결에서 제외한다.
- **검증:** 경계 시각, UTC와 브라우저 날짜 차이, DST, 오래된 활성 상태, 다중 체류 후보, 종료 확인 지연, 녹음 GPS와 장소가 명백히 충돌하는 경우를 fixture로 검증한다. 시각만 일치하지만 녹음 GPS가 없는 경우의 연결은 추정임을 모델에 보존한다.

### WEB-02 — 체류 목록·음성 묶음 컴포넌트

- **소유:** `web/src/location-stays/StayTimeline.tsx`, `StayDetails.tsx`, `copy.ts`, `stays.css`, 해당 컴포넌트용 fixture 화면.
- **선행:** WEB-01 fixture 계약. 실제 API 없이 병렬 구현 가능.
- **작업:** 음성을 포함한 펼침 가능한 체류 묶음, 음성 없는 체류, 이름 없는 체류의 ‘내 장소로 저장’ 콜백, 마지막 확인·중단·오래됨 상태를 만든다. 지도 실패와 무관하게 목록을 사용 가능하게 한다.
- **완료:** 녹음 선택은 기존 상세 열기 콜백으로 전달. 재생·수정 UI를 새로 복제하지 않는다. ‘계속 체류 중’은 fresh 상태에서만 표시. 기존 음성 목록 접근을 유지한다. 일별 체류 합계가 겹친 장소나 자정 조각 때문에 중복 가산되지 않는다.
- **검증:** 키보드 펼침/닫기와 포커스, 모바일/데스크톱, 한국어/영어, 음성 없음·위치 없음·부분 수신·오프라인·추적 종료·오래된 상태를 확인한다.

### WEB-03 — 내 장소 지도·편집기

- **소유:** `web/src/location-stays/PlaceMap.tsx`, `PlaceEditor.tsx`, `place-validation.ts`, `place-validation.test.mjs`, `places.css`.
- **선행:** SavedPlace 및 mutation adapter 인터페이스 합의. mock save 콜백으로 WEB-02와 병렬 진행 가능.
- **작업:** 체류 대표 위치에서 생성하거나 지도를 눌러 직접 생성한다. 이름·중심·반경 편집과 삭제를 제공한다. 마커/원의 편집은 Leaflet 기존 의존성을 사용한다. 지도와 별도로 좌표 입력도 제공한다.
- **완료:** 반경 150–2,000m, 최대 20개 제한과 서버 오류를 처리한다. 녹음이 없어도 지도 생성 가능. 선택한 체류 정확도를 실제 장소 경계와 구분한다. 겹치는 장소를 경고하고 연결 선택을 요구한다. 저장 후 워치 적용 대기를 표시한다. revision 충돌 시 최신 값 재조회 후 사용자에게 재적용 기회를 제공한다. 장소 변경으로 과거 연결을 일괄 수정하지 않는다.
- **검증:** 범위 밖·비정상 좌표/반경/빈 이름, 20개 한도, 동시 수정 충돌, 저장 실패·재시도, 취소 후 변경 없음, 지도 타일 실패와 키보드 입력, 장소 삭제와 체류 삭제의 구분을 확인한다.

### WEB-04 — 반복 체류 추천 계산·추천 목록

- **소유:** `web/src/location-stays/recommendations.ts`, `recommendations.test.mjs`, `PlaceSuggestions.tsx`, `suggestions.css`.
- **선행:** WEB-01 fixture와 대표 위치·정확도·세션 정보. 추천 항목은 WEB-03의 생성 콜백에 연결한다. mock으로 병렬 진행 가능.
- **작업:** 최근 7일에서 서로 다른 2일 이상·총 3회 이상 방문한 후보를 계산한다. 방문 횟수·누적 관측 체류 시간을 표시한다. 집·회사 이름을 추정하지 않는다.
- **완료:** 기존 장소와 중복 후보 및 숨긴 후보를 억제한다. 부정확한 위치로 인접 점포를 합치지 않는다. 공백 분할을 방문 2회로 세지 않도록 추천용 중복 억제를 하되, 체류 구간을 연결하거나 공백 시간을 누적하지 않는다. 숨김은 owner별로 유지하고 좌표 중심의 작은 변화로 재노출되지 않는다.
- **계약 결정:** 초기 군집 거리와 정확도 한계, 가까운 두 방문의 중복 억제 시간은 실제 데이터 검증 후 고정한다. 확실히 구분할 근거가 없으면 추천을 보류한다. 위치 좌표의 반올림만으로 안정 ID를 만들지 않는다. 후보가 보존 만료로 자격을 잃으면 제거한다.
- **검증:** 정확히 2일/3회 경계, 7일 창, 자정 넘김 한 방문, 공백 분할, 인접 장소, GPS 흔들림, 기존 장소 중첩, 숨김 후 재계산, 서로 다른 owner의 같은 위치를 포함한다.

### WEB-05 — 서버 adapter·동의·삭제·설정

- **소유:** `web/src/location-stays/repository.ts`, `useLocationStays.ts`, `LocationSettings.tsx`, `repository.test.mjs`.
- **선행:** 동기화 팀의 권한·API·동의·삭제·버전 계약 확정. 초기 mock adapter 작성은 가능하지만 실제 쓰기는 선행 계약 없이 구현하지 않는다.
- **작업:** 서버 응답을 WEB-01 타입으로 정규화한다. 실제 체류/장소 조회와 mutation, 별도 동의 및 철회, 소급 업로드 선택, 공통 체류 시간, 보존 안내, 기간/장소/전체 체류 삭제, 추천 숨김 persistence를 연결한다.
- **완료:** 음성 동의를 위치 동의로 취급하지 않는다. 서버가 반환한 유효 owner 범위만 사용한다. 로그아웃·연결 변경·권한 만료 시 위치 데이터 캐시를 비운다. 동의 철회 후 진행 중 요청 결과가 화면에 데이터를 되살리지 않는다. 중복 제출·revision 충돌·페이지네이션·부분 조회를 처리한다. 보존 기간 전체를 받지 못했다면 ‘추천 없음’을 단정하지 않고 불완전 조회를 표시한다.
- **검증:** mock adapter에서 오류·지연·순서 역전·취소·재시도·권한 상실을 확인한다. 실제 권한 격리와 삭제 후 워치 재업로드 방지는 동기화 팀의 통합 검증을 반드시 선행한다. mock 성공을 live 검증으로 보고하지 않는다.

### WEB-06 — 화면 연결·회귀 검증 (단일 통합 담당)

- **소유:** `web/src/main.tsx`, `MobileWorkspace.tsx`, 필요 최소한의 기존 `i18n.ts`/기존 스타일 import, `web/e2e/stays.spec.ts`, `web/e2e/stays-fixture.ts`.
- **선행:** WEB-01/02/03/05 완료. WEB-04는 독립 후속 연결 가능.
- **작업:** 새로운 독립 `LocationWorkspace` 조립 경계를 통해 모바일·데스크톱에 체류 탐색과 설정 진입을 연결한다. 기존 음성 검색/필터/지도/달력·재생·휴지통을 유지한다. 기존 RecordingMap를 확장해야 한다면 이 담당만 수정한다.
- **완료:** 동의 없음·연결 없음·기록 없음·일부 데이터·오래된 데이터·에러를 구분한다. 체류 없는 기존 계정의 화면이 정상 동작한다. 체류와 음성 필터의 적용 범위를 설명하고 일별 계산과 표시 시간대를 일치시킨다.
- **검증:** `npm test --prefix web`, `npm run build --prefix web`, 추가된 체류 E2E와 기존 모바일/포털 E2E. 삭제·만료·동의 철회 후 열린 상세/추천도 갱신되는지 확인한다. 좁은 화면·키보드·한영 문구·지도 없는 대체 경로를 확인한다. 실계정 통합 검증은 별도 환경에서 backend/watch 동기화가 준비된 후 수행한다.

## 실행 순서와 충돌 방지

1. 워치·동기화·웹의 계약을 고정하고 WEB-01의 fixture를 공유한다.
2. WEB-02, WEB-03, WEB-04를 독립 파일에서 병렬 진행한다. WEB-05는 백엔드 계약 확정 후 병렬 진행한다.
3. WEB-06 한 명만 기존 조립 파일을 수정하여 통합한다. 모든 작업자가 `main.tsx`, `MobileWorkspace.tsx`, 공용 CSS를 각자 수정하지 않는다.
4. 추천 군집 기본값은 현장 검증 결과로 확정한다. 단계별로 노출 가능 여부를 결정하며 미완성 API를 production UI에서 호출하지 않는다.

체류·추천은 민감한 위치 정보를 다룬다. 원시 이동 경로를 새로 수집하거나 음성 원본을 수정하는 방식으로 UI의 불확실성을 해결하지 않는다. 현재 다른 작업의 `voice-enrich` 코드 및 테스트 변경은 이 작업 소유 범위가 아니다.
