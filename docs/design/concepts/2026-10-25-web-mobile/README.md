## Google 로그인 추가 요구사항 반영

Discussion의 [추가 요구사항](https://github.com/stlim0727/haptilog/discussions/46#discussioncomment-19180660)을 반영했다. Google 로그인과 코드 연결, 기존 사용자의 계정 연결, 현재·이전 워치 선택, 새 워치 코드 확인, 브라우저 로그아웃과 계정에서 워치 연결 해제를 구분한다. 복구 불가능한 기록의 범위도 안내한다.

이는 아래 두 차례 UX 검토 이후의 **시안 확장**이다. 제품의 실제 Google OAuth 구현 완료를 의미하지 않는다. [상태별 화면·검증](google-account-notes.md)을 참고한다. 프로토타입의 계정 흐름을 보려면 `prototype.html`과 `account-prototype.js`를 같은 폴더에 둔다.

## 결과

- **목록:** 큰 소개와 다단 요약을 축약. 첫 기록은 390px 화면의 약428px 위치에서 시작한다. 목록 내부 스크롤을 없애고 페이지 스크롤만 사용한다.
- **상세:** 카드 선택 시 독립 화면으로 이동. 원본 음성 → 음성 텍스트 → 추출 정보 → 기록 위치 순서. 뒤로가기는 원래 보기·필터·검색·날짜·스크롤·카드 포커스로 복귀한다.
- **지도:** 목록 아래에 묻혀 있던 지도를 별도 보기로 제공. 장소별 기록을 선택하며 위치 있는 기록 수와 장소 수를 구분한다. 위치 없는 기록은 목록으로 안내한다.
- **달력:** 해당 날짜의 기록만 표시. 빈 날짜는 빈 상태와 최근 기록 날짜 이동만 제공하며 다른 날짜의 상세는 없다. 날짜 전체가 버튼이고 연월일·기록 수·선택 상태를 전달한다.
- **연결:** 코드 입력과 연결 버튼을 첫 화면에 배치. 하나의 숫자 입력 필드로 붙여넣기를 지원한다.
- **관리 기능:** 휴지통·CSV·Notion·연결 관리는 더보기. 휴지통은 기록의 분류 필터와 분리한다.

## UX 검토 1차 — 방향과 흐름

UX 디자이너 역할의 별도 에이전트가 기존 목록·캘린더·연결 캡처와 소스를 검토했다.

요청: 기록을 첫 화면 중심으로, 상세를 독립 화면으로, 목록 내부 스크롤 제거, 필터 명시, 휴지통 독립 목적지, 지도 즉시 접근, 코드 입력 우선.

반영: 위 흐름을 HTML 시안에 구현. 320px에서 달력 7열 전체에 44px 너비를 강제하면 넘치므로 날짜 셀 너비 약40.9px / 높이47px로 절충했다. 360px 이상은 날짜 셀 너비44px 이상이다.

## 사용과 검증 범위

prototype.html을 브라우저에서 열면 목록·상세·지도·달력·필터·휴지통·코드 입력 흐름을 확인할 수 있다. URL의 `?view=pair`, `?view=calendar&empty=1`, `?view=detail&id=2`로 특정 상태를 바로 열 수 있다.

320·360·390·430px의 5개 보기에서 문서 가로 넘침이 없음을 확인했다. 날짜 키보드 Enter, 빈 날짜 기록 노출 없음, 필터 유지·카드 포커스 복원, 임의 6자리 데모 연결을 검사했다. 수치는 final/validation.json, 추가 검사는 final/additional-validation.json에 보존한다.

200% 글자 확대는 모든 요소의 계산된 글자 크기를 2배로 만든 320px 스트레스 검사다. 브라우저·운영체제의 실제 글자 확대 또는 모바일 보조기기 검증을 대신하지 않는다. 영어 버전과 모바일 Safari·실기기는 검증하지 않았다.

시안은 한국어 예시 데이터만 사용한다. 지도는 배치 설명용 SVG이고, 원음 재생·텍스트 저장·삭제·외부 연결은 실제 동작하지 않으며 버튼을 누르면 시안임을 안내한다. 실제 백엔드와 사용자 데이터는 사용하지 않았다. 제품 구현 시 분석 상태/실패, 지도 타일 실패, 권한 만료, 편집 저장/이탈, 영구 삭제 확인 상태를 추가 검증해야 한다.
