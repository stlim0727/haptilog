# HaptiLog Watch UX — Phase 1 제안

상태: UX 디렉터 에이전트와 도출한 구현 계획. 앱 구현은 시작하지 않았다.
기준: main `a01bc19`, [종합 비교 Discussion #35](https://github.com/stlim0727/haptilog/discussions/35), 기존 빠른 녹음 접근 요구 [#25](https://github.com/stlim0727/haptilog/issues/25) / [PR #26](https://github.com/stlim0727/haptilog/pull/26).

## 목표와 범위 결정

**현재 화면 구조에서 녹음·기록 찾기·재생·설정의 주요 행동을 쉽게 식별하고, 보던 위치로 돌아올 수 있게 한다.**

Phase 1은 현재 세로 홈, 목록 카드, 상세, 설정 Activity 구조를 유지한다. 삼성 기본 워치 음성 녹음의 작업별 위계를 참고하되 전체 화면 구성이나 기능을 그대로 복제하지 않는다. 실제 앱 첫 화면이 좋아졌는지 기본 글꼴에서 먼저 확인하고, 확대 글꼴 접근성도 함께 보장한다.

### 포함

- 시계와 스크롤의 겹침, 과도한 초기 상단 공백 교정.
- 녹음/중지와 보조 설정 진입의 강조도 및 핵심 문구 통일.
- 내용을 식별하기 쉬운 목록 카드와 목록 위치 보존.
- 상세 상단 재생, 펼칠 수 있는 전문, 명확한 로컬 삭제 확인 및 실패 안내.
- 현재 설정 화면 내부의 얕은 그룹화·순서 정리, 버전/빌드 후순위화.
- 수정하는 UI 문구의 한국어/영어 문자열 리소스, 상태별 비교 캡처와 회귀 검증.

### 후속 Phase로 미룸

- 별도 Capture/Recordings 화면과 새 탐색 구조.
- Wear Material 3 전면 이행, 전체 디자인 시스템 재구축.
- 새 녹음 일시정지, 재생 탐색/속도 조절/진행 링, 실시간 파형.
- AI 모델, 서버/DB/API, 동기화 정책 및 원본 저장 방식 변경.
- 사용자 작성 제목·이름 수정, 새 분류/검색 기능.
- 클라우드 동의·지원 장문 전체 재작성/번역 프로젝트. 이번에 고치지 않는 기존 긴 문구의 언어 혼재는 후속 항목으로 명시한다.
- 배포/Play 제출: Phase 1 도출 작업에는 포함하지 않는다.

## 작업 묶음과 완료 기준

| 순서 | 작업 | 실제 변경 | 완료 기준 |
| --- | --- | --- | --- |
| P1-1 | 공통 화면 틀·시각 위계 | Main/Detail의 시계와 스크롤 연동. 상세/설정의 초기 항목 정렬·상단 공백 교정. 수정할 버튼·텍스트의 공통 색/간격/역할 정리. | 스크롤 중 시계가 제목·버튼을 덮지 않는다. 기본 글꼴 첫 화면에서 핵심 콘텐츠/행동이 실제로 앞당겨진다. 스크롤 표시·회전 입력 유지. |
| P1-2 | 녹음 홈과 설정 입구 | 기존 단일 녹음 제어를 유지하며 대기는 ‘녹음’, 진행 중에는 ‘중지’를 명시하고 경과 시간 표시. Settings 위치는 유지하되 아이콘+라벨의 중립색 항목으로 낮춘다. | 외부 진입 시 Record가 바로 보인다. 기존 한 번 눌러 시작/다시 눌러 종료와 햅틱 계약이 같다. 설정은 아이콘만으로 숨기거나 무한 목록 끝으로 밀지 않는다. |
| P1-3 | 목록 카드와 복귀 상태 | 짧은 AI 요약을 첫 줄에, 날짜·길이는 보조 정보로. 미분석 녹음은 로케일에 맞춘 날짜 기반 식별 문구. 목록 상태를 화면 분기 밖에서 유지하고 복귀 원인을 구분한다. | 긴 기록 목록에서 상세/설정을 보고 Back하면 같은 카드 부근으로 돌아온다. 요약을 사용자 작성 제목으로 저장하거나 원본 메타데이터를 바꾸지 않는다. 항목 삭제/정렬 변경 시 존재하는 이웃 항목으로 복구한다. |
| P1-4 | 상세와 안전한 삭제 | 짧은 식별 정보 → 재생/재생 중지 → AI 요약 → 전체 텍스트 펼치기 → 부가 정보/내보내기 순서. ‘워치에서 삭제’는 낮은 강조도와 확인으로 제공. | 기본 글꼴의 상세 첫 진입에서 짧은 식별 정보와 재생 제어가 실제 원형 표시 영역 안에 함께 보인다. 전문을 실제로 펼쳐 끝까지 읽을 수 있다. 삭제 취소는 아무 파일도 지우지 않는다. 실패 시 남은 오디오·메타데이터를 재확인하여 유효한 상세/목록에서 부분 실패·파일 없음에 맞는 안내를 제공한다. 기존 재생 실패/파일 없음에 기본 피드백을 제공한다. |
| P1-5 | 설정의 얕은 정리 | 같은 화면에서 연결·동기화 → 도움말/개인정보/신고 → 앱 정보 순서로 그룹화. 버전/빌드/업데이트는 후순위. 웹 연결은 코드 생성 동작을 앞당긴다. 동의/신고 상태의 제목은 현재 작업에 맞춘다. | 새 설정 하위 화면 체계를 만들지 않는다. 기존 연결·취소·만료·해제·신고 기능을 잃지 않는다. 동의 전문과 거절 경로는 그대로 접근 가능하며 자동 동의/업로드가 생기지 않는다. |
| P1-6 | 비교·회귀 검증 | 기본/큰 글꼴의 이전·이후 화면과 핵심 시나리오 기록. 관련 Gradle 체크와 의미 있는 상태/행동 테스트. | 아래 검증 기준을 충족한다. 새 UI가 접근성 수정 이전 상태로 돌아가지 않고 원본/녹음 동작도 보존한다. |

수정하는 액션·제목·상태·확인/오류 문구는 ko/en 리소스로 함께 정의한다. 모든 색을 코럴로 바꾸지 않고, 녹음 관련 강조와 보조/파괴적 행동의 역할을 구분한다. 글자 크기를 줄여 시안을 억지로 맞추지 않는다.

## 복귀 규칙 — 기존 요구와의 정합성

#25는 **앱 실행 시 녹음 버튼을 찾으려고 스크롤하지 않게 해 달라**는 요구다. #26은 launcher/tile의 기존 task 재진입 문제를 `모든 ON_RESUME → 맨 위`로 해결했다. Phase 1은 빠른 외부 재진입을 유지하면서 내부 Back을 구분한다.

| 진입/복귀 사건 | Phase 1 제안 동작 |
| --- | --- |
| Cold launch / launcher에서 다시 열기 / 명시적인 빠른 녹음 진입 | 녹음 제어가 바로 보인다. Tile/complication의 기존 녹음 명령도 유지한다. |
| 상세에서 Back | 보던 목록 카드와 스크롤 위치로 복귀. 상세를 떠날 때 기존 재생 종료 동작 유지. |
| 설정에서 Back | 설정 진입 전 목록 위치로 복귀. 외부 launcher 재진입과 같은 사건으로 취급하지 않는다. |
| 삭제한 기록에서 목록으로 복귀 | 존재하는 인접 기록 또는 비어 있는 목록으로 안전하게 복귀. |
| 프로세스/화면 재생성 | 내부 화면 재생성은 현재 경로의 위치·펼치기 상태를 복원하고, 없어지는 기록은 안전한 목록으로 복귀. 명시적 외부 진입이 있으면 위의 녹음 접근 규칙을 우선한다. 별도 제품 탐색 구조는 도입하지 않는다. |

설정 Back 예외는 이번에 명시적으로 제안하는 세부 규칙이며 기존 제품이 이미 보장한다는 뜻이 아니다. 구현 시 두 경로를 실제로 구별해 테스트해야 한다. 모든 resume의 리셋을 단순 제거하는 방식은 완료로 인정하지 않는다.

## 화면 수용 기준

- **홈:** 기본 글꼴의 192dp/227dp 진입 화면에 식별 가능한 녹음 제어. 녹음 중에는 중지 의미가 분명하며 경과 시간이 읽힌다.
- **목록:** 요약이 있는/없는/긴 항목 모두 내용을 식별할 수 있다. 미리보기의 제한된 줄 수·말줄임은 허용하되 상세에서 전체 내용에 접근할 수 있다. 상태 문구는 클라우드 꺼짐과 오류/대기를 혼동시키지 않는다.
- **상세:** 기본 글꼴의 첫 진입에서 짧은 식별 정보와 재생 제어가 실제 원형 표시 영역에 보인다. 2× 글꼴에서는 스크롤로 접근할 수 있으며 모든 항목이 첫 화면에 보일 필요는 없다. 기존 기능은 펼침/스크롤로 모두 접근 가능하다. 재생 조작에 일시정지·탐색 기능이 이미 있다고 표현하지 않는다.
- **설정:** 버전/빌드가 첫 번째 주요 기능을 밀어내지 않는다. 수정한 핵심 기능의 라벨·상태가 로케일에 맞는다. 동의 거절 후 로컬 녹음이 계속 가능하다.
- **공통:** 시계/본문/버튼의 겹침 없음. 최소 48dp 터치 대상과 시스템 글꼴 확대, 스크롤바, 회전 입력 유지. 스크린리더에서도 녹음/중지, 재생/재생 중지, 전문 펼침/접힘, 삭제 확인의 이름·역할·상태를 구분한다. 이 기준은 스크린샷만으로 검증했다고 하지 않는다. 큰 글꼴에서는 항목이 늘어나 스크롤해도 된다. 모든 내용을 한 화면에 넣는 조건은 두지 않는다.

## 검증과 산출물

### 시각 검증

- 192dp / 227dp 원형 화면 × 기본 1.0 / 2.0 스트레스 글꼴. 지원 기기의 실제 최대 글꼴도 확인한다.
- 각 조합에서 홈(대기/진행), 목록, 상세 상단·펼친 전문·행동 영역, 설정 입구·첫 화면의 캡처와 UI 계층을 비교한다.
- ko/en 핵심 문구를 모두 점검한다. 긴 문구·미분석 녹음·긴 목록·로컬 전용·실패 상태를 대표 데이터로 확인한다.
- 단순히 글자가 잘리지 않는지에 더해, 기본 글꼴에서 다음 행동을 찾기 쉬워졌는지 UX 디렉터가 이전/이후 화면으로 검토한다.

### 행동/회귀 검증

1. 외부 재실행 시 즉시 녹음 접근, 상세/설정 Back 시 목록 위치 복원, 화면 재생성 및 삭제한 항목 처리.
2. 시작/중지 및 최대 시간 제한, 로컬 음성·메타데이터가 오프라인·프로세스 재시작 후 유지됨. 새 UI 때문에 저장 전 업로드가 발생하지 않음.
3. 재생/재생 중지, 상세를 떠날 때 재생 종료, 파일 없음/재생 실패 안내.
4. 로컬 삭제 확인·취소·실패·성공. 현재 오디오 삭제 후 메타데이터 삭제 실패가 가능한 경로를 포함하여 남은 파일 상태를 확인하고 안내한다. 원본 복원·Undo·원자적 삭제는 약속하지 않으며, 클라우드 사본까지 삭제되었다고 표시하지 않는다.
5. 동의 거절, 연결 코드 취소/만료, 동기화 꺼짐에서의 핵심 경로. 실계정이나 실제 음성 업로드는 레이아웃 검증에 사용하지 않음.
6. `assembleDebug lintDebug testDebugUnitTest`와 변경된 상태 전환에 필요한 테스트 통과. 실제 Galaxy Watch에서 녹음 햅틱/음향 간섭과 조작성 회귀 확인. 실물 검증 미실시는 명시적으로 남김.

### 구현 PR 권장 분할

- **PR A:** P1-1 + P1-2 — 화면 틀/강조도/녹음·중지 의미.
- **PR B:** P1-3 + P1-4 — 목록·상세·복귀 상태·로컬 삭제.
- **PR C:** P1-5 + 최종 P1-6 — 설정 정리와 전체 흐름 검증.

각 PR에 해당 화면의 기본/확대 글꼴 이전·이후 캡처와 관련 행동 검증을 첨부한다. PR A의 기본 글꼴 위계를 검토한 뒤 B/C에 적용하여 시각 규칙이 화면마다 갈라지지 않게 한다. Phase 1 완료는 구현 PR/검증 완료를 뜻하며 Play 승인·출시 완료와는 별개다.

## 후속 검토 목록

Capture/Recordings 분리의 탐색 비교, 완전한 ko/en 장문 검토, 동의 내용을 유지한 전면적인 읽기 구조 개선, M3 마이그레이션, 재생 전용 화면 및 추가 조작 등은 별도 범위로 정한다.
