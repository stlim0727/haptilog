HaptiLog Privacy Policy

Effective Date: October 18, 2026 • Application: HaptiLog for Wear OS (com.haptilog.watch) & Web Portal
HaptiLog is designed around local-first capture and privacy by design. Audio memos are recorded only when explicitly initiated by the user, stored locally on watch flash memory, and never sold or shared with advertising third parties.

Adults 18+: HaptiLog is intended for adults. Optional cloud synchronization and AI processing require an explicit declaration that you are at least 18 and consent to processing. This declaration is not independent age verification. Declining leaves watch recording local. Turning cloud sync off stops future watch synchronization and queues server consent withdrawal when online; requests already sent may finish. Existing cloud copies remain until deleted in the portal or through a support request.

1. Information We Collect and Process

A. Audio Recordings (Microphone)

HaptiLog records audio strictly when you explicitly tap to start a recording on the watch display, Wear OS Tile, or Complication.

  • Local Storage: Audio files (AAC/M4A) are saved to your watch’s private application storage immediately. Offline voice logging works without an internet connection.
  • Cloud Sync & AI Processing: If cloud sync is active, audio files are securely uploaded via encrypted HTTPS to our backend (Supabase) to generate text transcriptions and structured summaries (expense amounts, tasks, journal notes) using Google Gemini AI.
  • No Continuous Listening: HaptiLog does not listen passively, record in the background without user initiation, or collect ambient audio.

B. Location Data (GPS)

When location permission is granted, HaptiLog captures a single geographic snapshot (latitude, longitude, altitude, and velocity) at the moment of recording.

  • Purpose: Geotagging your voice memos (e.g. marking where an expense was incurred, field notes taken, or running intervals logged).
  • Scope: Location capture runs exclusively during active recording sessions and stops immediately when recording terminates. We do not track your real-time location outside active recording sessions.

C. Optional Diagnostic & Crash Reports

Diagnostic reporting is off by default. If you explicitly opt in through Watch Settings:

  • Uncaught JVM exception class names, limited HaptiLog code locations (class, method, and line number), app build version, device manufacturer/model, and Android OS level are collected to fix bugs. Reports are linked to your anonymous cloud user ID.
  • Strict Exclusions: Crash reports never contain audio data, transcripts, GPS coordinates, file paths, device IDs, or exception message strings.

D. Support Reports and Cloud Identity

When you choose to send an issue report from Watch Settings, we collect the description you enter, a report ID, app/build version, device manufacturer/model, Android API level, and an anonymous cloud user ID. Issue submission is optional and separate from the crash-report switch. Do not include sensitive personal information in your description.

Optional cloud features use an automatically generated anonymous user ID and authenticated sessions to protect your recordings, pair browsers, and associate support reports. You do not need to provide a name, email address, or password to use the watch app. Synchronized transcripts, structured summaries, and corrections are stored with the source recording.

If you choose to record purchase or workout notes and enable cloud processing, their contents may include purchase history (such as amounts, currencies, and merchants) or fitness information (such as exercise observations). HaptiLog organizes these into expense and workout notes. It does not connect to a bank, process payments, measure vital signs, or provide financial or medical advice.

2. How We Use and Share Information

We use captured data exclusively to deliver HaptiLog's core voice logging, transcription, and contextual organization features:

  • AI Transcription & Structuring: Audio data and recording timestamps are sent to Google Gemini APIs through our backend for transcription and organization. GPS coordinates, user identifiers, and internal storage paths are strictly excluded from AI provider requests. Cloud sync is off by default on the watch; enabling it can upload previously saved completed recordings as well as new ones. Spoken content within the audio recording is transcribed and processed as data by the model.
  • No Advertising or Profiling: We do not serve advertisements, sell user data, or share personal information with data brokers or tracking networks.
  • Map Display: When reviewing locations on the web portal, map tiles are provided by OpenStreetMap. Only the displayed map coordinates and page origin are sent to tile servers; no user voice, audio, or transcript data is transmitted.

3. Data Storage, Security & Retention

  • Encryption in Transit: All communications between the watch, web portal, and cloud services use TLS/HTTPS encryption.
  • Access Control: Data stored in our database is protected using PostgreSQL Row-Level Security (RLS) ensuring each user can access only their own records.
  • Web Pairing Security: Web portal connections authenticate using short-lived HMAC-verified codes and cryptographically scoped session tokens.
  • Local Deletion: Deleting a recording on the watch removes its local files. It does not delete an already uploaded cloud copy. Revoking a browser connection removes its future access, but does not delete cloud recordings or copies already downloaded.
  • Cloud Consent: When you enable cloud features, we record your adult declaration, consent version, and consent/withdrawal time against your anonymous cloud identity. This is optional and is not a date-of-birth or identity check.
  • Retention: Local recordings remain until you delete them or remove the app's data. Cloud recordings, location snapshots, transcripts, summaries, and corrections remain until permanently deleted through the portal or removed following a verified request. Moving a recording to Trash is reversible and does not delete its stored audio. Support and crash reports are retained for troubleshooting and manually removed when no longer needed; there is no automatic 90-day deletion schedule.

Request deletion of HaptiLog cloud data

In a connected web portal, move a recording to Trash and use Delete permanently to request deletion of that recording and its associated content. For all cloud data, anonymous identity, support reports, or help with a deletion that did not complete, use the email process below.

Email support@keepory.app with the subject HaptiLog data deletion. Specify whether you want all cloud data deleted or particular recordings or reports removed. Include your portal user identifier or a support report ID if available so we can locate your data. Never send a password, pairing code, or session token. We may ask you to verify control of the associated watch or browser before deleting data.

A verified request can cover uploaded audio, location metadata, transcripts, summaries, corrections, support/crash reports, and the associated anonymous cloud identity. Disconnecting a browser or uninstalling the watch app alone does not request cloud deletion. We will explain any data that must be retained and the applicable period when handling your request.

4. Permissions Used by HaptiLog

  • RECORD_AUDIO: Capturing voice memos initiated by the user.
  • ACCESS_FINE_LOCATION & ACCESS_COARSE_LOCATION: Geotagging memos with location coordinates at recording time.
  • FOREGROUND_SERVICE_MICROPHONE & FOREGROUND_SERVICE_LOCATION: Maintaining uninterrupted recording with an ongoing status notification while the watch screen enters ambient sleep mode.
  • VIBRATE: Providing tactile living pulse feedback during recording.
  • WAKE_LOCK: Keeping the CPU awake strictly during active recording.
